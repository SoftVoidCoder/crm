# Korda CRM

Внутренняя система компании Korda для работы с **договорами**, **документами компании** и **корпоративной почтой**. Сотрудники входят под корпоративной почтой `@korda.spb.ru`, директор управляет доступами.

- **Рабочий сайт:** https://85-31-45-168.sslip.io/app (собственный VPS)
- **Код:** https://github.com/SoftVoidCoder/crm, ветка `main`
- **Старая копия на Render** (`korda-crm-7suw.onrender.com`) — не основная, со своей базой; продолжает собираться из `main`, но рабочие данные живут на VPS.

## Что умеет система

В меню четыре раздела: **Договоры**, **Документы компании**, **Почта**, а директору ещё **Доступы**. Остальные модули (проекты, склад, бухгалтерия, ERP и т. п.) остались в коде для совместимости, но скрыты из меню.

### Договоры
Реестр в стиле «Договор Партнёр», вкладки **«Реестр договоров»** и **«Контрагенты»**.

- **Реестр:** папки слева (Все, Удалённые, свои папки), таблица на весь экран, поиск, период, статус, фильтр по каждой колонке, поиск по тексту внутри файлов (PDF/DOCX/TXT), «Мои согласования», выгрузка в Excel/CSV/печать, массовая смена статуса, корзина с восстановлением.
- **Цвет строк:** истекающие, просроченные, просроченные и открытые согласования.
- **Типы документов с автонумерацией:** префикс + номер с нулями до разрядности + постпрефикс + год, например `ДПТ-0001/2026`. Можно создать договор без автонумерации или со случайным номером.
- **Карточка договора** — 19 разделов: Основные (даты, суммы, НДС с авторасчётом, пролонгация, подписание, статус, тексты «Предмет / Закрытие / Объект / Страхование…»), Контрагенты (стороны и роли), Платежи и неустойка, Согласования, Файлы, Документы/Спецификации, Этапы, Судебные дела, Претензии, Прочее, Доп. соглашения, Субподряды, Задачи, Затраты, Письма, Права доступа, Движения, Доверенности, Пропуска.
- **Пользовательские параметры** (свои поля для всех договоров), настройка видимых разделов, **рентабельность** и **диаграммы**, печать карточки, конверта, листа согласования.
- **Просмотр** — отдельная красивая карточка только для чтения со всем, что заполнено, и кнопкой «Изменить».
- **Контрагенты:** справочник организаций, поиск по ИНН через DaData, отметка «наша организация».

### Согласование и уведомления
- Согласующие, ответственный, инициатор, исполнители задач выбираются **только из сотрудников**; отдел и должность подтягиваются из «Доступов».
- Решение по строке согласования принимает **только сам согласующий или директор**.
- Если у договора заполнены «Права доступа», его видят только директор, автор, ответственный, инициатор, люди из списка и согласующие (последние — только просмотр).
- **Уведомления** — в колокольчике CRM и **HTML-письмом** с карточкой договора, листом согласования и кнопкой «Открыть договор»:
  - согласующему — когда его добавили;
  - автору / ответственному / инициатору — каждое решение;
  - остальным согласующим — если договор отклонён;
  - всем участникам — когда согласовали все;
  - исполнителю — новая задача.
- **Напоминания** (каждые 30 минут, только 9:00–20:00 МСК, каждое — один раз): срок согласования сегодня / просрочен, подходит дата окончания договора, договор истёк, но «Действует», просрочен плановый платёж.

### Документы компании
Реестр входящих, исходящих и внутренних документов в той же раскладке, что договоры: журналы слева (Все, Входящие, Исходящие, Внутренние, Черновики, Архив), таблица, фильтры, подсветка «срок прошёл / скоро / нет файла», карточка просмотра, окно «Изменить» с заменой файла, перенос в архив, удаление только с подтверждением.

### Почта
- Корпоративные ящики Korda Mail (Exchange `mail.korda.spb.ru`) через **EWS**: входящие, ответы, вложения документов CRM, фильтры, закреплённые переписки, отправленные.
- Ящик **подключается сам**: при регистрации или при первом входе сотрудника корпоративной почтой. Ручной привязки в интерфейсе нет.
- Ящик принадлежит одному аккаунту CRM (`email_account_owners`), все действия проверяют владельца.
- Синхронизация в фоне, загружаются только новые письма.
- У сервера `mail.korda.spb.ru` в DNS есть мёртвый адрес `94.159.95.60` — код сам выбирает живой IP (`_exchange_ews_session`).

### Доступы и регистрация
- Роли: **Директор** (полный доступ, «админ») и **Сотрудник**.
- Сотрудник сам подаёт заявку на странице `/static/register.html`: ФИО (фамилия и имя обязательны), отдел, должность, **корпоративная почта и пароль от неё** — пароль проверяется на почтовом сервере Korda, поэтому чужую почту не зарегистрировать.
- Директору приходит колокольчик и письмо; в «Доступах» он **принимает** (выбирает роль) или **отклоняет** (с причиной) заявку. Заявителю приходит письмо.
- Сотрудники без корпоративной почты добавляются директором вручную («Добавить сотрудника»).
- Вход корпоративной почтой и её паролем; если пароль от почты сменился, CRM примет новый после проверки на почтовом сервере.
- Аккаунт директора: логин `Admin` (почта `k.kondratev@korda.spb.ru`).

## Технологии

- **Python 3.12+ / FastAPI / uvicorn**, серверные шаблоны **Jinja2**, фронтенд — обычный JS и CSS без сборки.
- **PostgreSQL 16** (через `psycopg`), SQL-миграции в `migrations/`.
- Почта: EWS через `requests` + `requests-ntlm`; системные письма — SMTP (Gmail с паролем приложения).
- Поиск по ИНН — DaData; текст из PDF — `pdftotext` (пакет `poppler-utils`).

## Настройки (переменные окружения)

На сервере лежат в `/opt/korda/.env` (доступ только у сервиса). **Секреты в репозиторий не кладём.** Пример — `.env.example`.

| Переменная | Зачем |
|---|---|
| `KORDA_ENV` | `production` на сервере |
| `KORDA_APP_SECRET` | секрет для cookie и шифрования паролей ящиков |
| `KORDA_DATABASE_URL` | PostgreSQL; на VPS через сокет: `postgresql:///korda?host=/var/run/postgresql` |
| `KORDA_PUBLIC_BASE_URL` | адрес сайта для ссылок в письмах |
| `KORDA_COOKIE_SECURE` | `1` при HTTPS |
| `KORDA_DIRECTOR_EMAIL`, `KORDA_DEFAULT_ADMIN_LOGIN` | учётка директора при первом запуске |
| `KORDA_SMTP_USER/PASS/HOST/PORT` | ящик для системных писем (Gmail + пароль приложения, `smtp.gmail.com:465`) |
| `KORDA_DADATA_TOKEN`, `KORDA_DADATA_SECRET` | поиск контрагентов по ИНН |
| `KORDA_MAIL_SYNC_BATCH`, `KORDA_MAIL_IMAP_TIMEOUT`, `KORDA_MAIL_SMTP_TIMEOUT` | параметры почты |

## Запуск локально

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить, нужен доступный PostgreSQL
.venv/bin/uvicorn main:app --reload --port 8000
```

Открыть http://localhost:8000/app. Таблицы и миграции создаются при старте.

## Сервер (VPS) и выкладка

- Ubuntu 24.04, `85.31.45.168`. Код — `/opt/korda/app`, окружение Python — `/opt/korda/venv`, настройки — `/opt/korda/.env`, файлы — `/opt/korda/app/uploads`, резервные копии базы — `/opt/korda/backups`.
- Сервис **`korda-crm`** (systemd, uvicorn на `127.0.0.1:8000`), перед ним **nginx** с HTTPS (Let's Encrypt, автопродление) и раздачей `/static`.
- **Выкладка** (миграции применяются сами при перезапуске):

```bash
git push origin main
git archive main | ssh root@85.31.45.168 'tar -x -C /opt/korda/app && chown -R korda:korda /opt/korda/app && chmod -R g+rX /opt/korda/app/static && systemctl restart korda-crm'
```

- **Логи:** `journalctl -u korda-crm -f`; запросы с временем ответа — `/var/log/nginx/korda.log`.
- **Резервная копия базы:**

```bash
ssh root@85.31.45.168 'sudo -u korda pg_dump "postgresql:///korda?host=/var/run/postgresql" | gzip > /opt/korda/backups/korda-$(date +%F).sql.gz'
```

- После изменений фронтенда поднимать `?v=` у подключённых JS/CSS в `templates/index.html`, иначе браузеры возьмут старую версию из кеша.
- Рискованные изменения сначала проверяются на временной копии на том же сервере: отдельная база `korda_test`, порт 8001, доступ через SSH-туннель. Рабочую базу не очищать и не пересоздавать.

## Правила

- Не коммитить пароли, токены, `.env`, дампы базы и пользовательские файлы.
- Скрытие пункта меню ≠ удаление: старые модули и их данные не трогать без отдельной задачи.
- Права проверяются на сервере (роутеры), а не только в интерфейсе.
- Сервер слабый по CPU: избегать тяжёлых вычислений в запросах, долгие операции (почта, письма) — в фоне.
